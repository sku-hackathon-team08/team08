# DB 명세

> 상태: 해커톤 업무 모델·DB 연결·트랜잭션·Alembic 마이그레이션을 구현했습니다.

저장 데이터의 구조와 일관성을 유지하는 규칙을 관리합니다. DB 기술 선택과 적용 상태는 [아키텍처](../architecture.md#백엔드-환경과-db)를 참고합니다.
공통 설계 기준·네이밍 권고와 항목별 합의 상태는 [DB 설계 가이드](../guides/database.md)에 있습니다. 이 폴더에는 실제 테이블·관계·제약을 기록합니다.
필요한 명세가 생기면 주제별 문서를 이 폴더에 만들고 아래 목록에 연결합니다.

## 명세 목록

- [업무 저장·트랜잭션·마이그레이션](storage.md): 행사·세션·분석·신고·지원·이력·멱등 기록과 SQLite/PostgreSQL 제약.

## 작성 대상

- 테이블·컬럼·타입·기본값·필수 여부
- ERD·관계·외래 키·고유 제약·인덱스
- 필요한 트랜잭션 범위·삭제 및 보존 규칙
- 스키마 변경·마이그레이션 시 데이터 처리 규칙

위 항목은 작성 범위이며 기능이 정해지면 필요한 내용만 작성합니다.

## 다른 문서와의 경계

- 사용자 동작·업무 규칙·인수 조건은 [기능 명세](../features/index.md)에 두고, 여기서는 저장 구조·제약으로 연결합니다.
- 공개 요청·응답 필드는 [API 명세](../api/index.md)에 둡니다. DB 컬럼과 API 필드가 같다고 가정하지 않습니다.
- 외부 제공자와의 통신·데이터 매핑은 [외부 연동 명세](../integrations/index.md)에 두고, 저장이 필요한 데이터 구조는 이 폴더의 문서로 연결합니다.
- 레이어·의존 방향은 [아키텍처](../architecture.md), 개발 방법은 [개발 가이드](../guides/index.md)를 따릅니다.

문서 추가·변경 시 [인덱스 갱신 기준](../sot.md#인덱스-갱신-기준)을 따릅니다.
