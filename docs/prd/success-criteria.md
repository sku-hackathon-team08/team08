# 성공 기준·시연

> PRD v1.2 · 제품 인수 방향 확정. 수치형 성능 목표와 실제 검증 결과는 미정입니다.

## 제품 성공 조건

스태프의 신고가 관리자 지도에서 확인되고, 한 명의 담당자가 분류를 확정한 뒤 지원과 완료까지 이어져야 합니다. 누가 어떤 조치를 했는지 남아야 하며, 세 종류의 취소가 서로 다른 결과를 내야 합니다. 기능 명세의 인수 조건은 구현 이후 검증할 기대 결과이며 이번 문서 변경으로 통과했다고 간주하지 않습니다.

## 핵심 시연

1. 준비된 행사 코드로 스태프와 관리자 각각 진입하고 제공자 구축 구역 지도를 확인합니다.
2. 앱에서 음성 신고를 녹음하고 분석 결과를 수정한 뒤 최종 전송합니다. 텍스트도 같은 확인 흐름을 시연합니다.
3. 관리자가 지도·원문을 확인하고 직접 처리하기로 담당 배정과 분류를 동시에 확정합니다.
4. 다른 관리자가 지원에 참여하고 본인 참여 취소·재참여를 합니다. 담당자가 지원요청을 종료한 후 재요청하여 새 참여가 필요한 것을 확인합니다.
5. 담당자가 메모 없이 완료하고 스태프 내역·리포트에서 결과를 확인합니다.
6. 별도 신고로 담당 배정 취소 후 재배정과, 다른 관리자의 사유 입력 신고 취소를 구분해 시연합니다.
7. 최초 접수 기준을 초과한 미확인 신고가 상단에 표시되는 것을 확인합니다.

## 검증 범위

[행사 진입](../features/event-entry.md), [신고 입력](../features/report-intake.md), [처리·지원](../features/report-lifecycle.md), [관제](../features/command-dashboard.md), [리포트](../features/activity-report.md)의 AC를 구현 검증에 사용합니다.

실기기 마이크·야외 가독성·네트워크 단절, 브이월드 지도·접근 경로, PDF와 데이터 보존은 실제 환경에서 확인해야 합니다. GPS는 현재 범위에서 사용하지 않으며 고정 위치가 신고와 관제에 일관되게 전달되는지 확인합니다. 미정 상태의 예외 흐름을 시연 완료로 보고하지 않습니다. 응답속도·동시 사용자·정확도 등의 수치 목표는 측정 조건과 함께 추후 정합니다.
