# API 문서

프론트·백엔드가 함께 참고하는 API 계약의 시작점입니다. 기능별 문서는 이 폴더에 작성합니다.
현재는 앱 실행 확인용 API만 구현했으며 서비스 API는 미정입니다.

## 공통 계약과 검토 목록

| 문서 | 내용 | 상태 |
|---|---|---|
| [공통 오류 응답](errors.md) | status·detail·code·errors, 처리 책임·구현 완료 기준 | 기본 형식 합의·미구현. 필드 오류 세부 표현은 검토안 |
| [프론트·백엔드 계약 검토](integration-contracts.md) | 네이밍·null·시간·성공 응답·인증·목록·재시도·스트리밍 | 검토안 |

## 문서 작성 기준

- 기능별 문서에 상태, 메서드·경로, 목적, 인증 여부, 요청·응답 예시, 오류·제약을 적습니다.
- 구현 전 계약을 먼저 합의하고, 미구현 항목은 상태에 표시합니다. 프론트는 필요한 기능 문서부터 확인합니다.
- API 변경 시 이 문서의 계약·백엔드 구현·프론트 호출부·테스트를 함께 확인합니다.
- `docs/api/`는 합의한 계약과 사용 맥락, FastAPI의 `/openapi.json`·`/docs`는 현재 구현된 스키마와 호출 확인을 담당합니다.
- 계약과 OpenAPI가 다르면 어느 쪽이 바뀌어야 하는지 확인합니다. 자동 생성된 스키마가 합의한 계약을 자동으로 대체하지 않습니다.
- 공통 오류는 [오류 계약](errors.md)에 기본 형식을 합의했으며 아직 구현하지 않았습니다. JSON 필드 네이밍·인증 등은 [추가 계약 검토](integration-contracts.md)에서 필요한 시점에 정합니다. 설명용 예시를 구현된 기능이나 확정 코드 목록으로 취급하지 않습니다.

DB·ERD 등 기술 명세는 [기술 명세 목록](../specs/index.md), 문서 책임은 [SOT](../sot.md)를 참고합니다.
