# DB 설계 가이드

> 상태: 팀 합의에 따라 확정 선택·기본 방향·권장사항·선택 적용·추후 결정을 구분합니다. DB URL 선택은 구현했으며 DB 연결·세션 수명을 구현했고 실제 DB 모델·마이그레이션은 미구현입니다.

이 문서는 여러 데이터 모델에 적용할 공통 설계 기준입니다. 실제 테이블·컬럼·ERD·도메인별 제약은 [DB 명세](../db/index.md)에 작성하고 이 가이드를 연결합니다.
DB 제품·ORM·드라이버의 선택 상태와 코드 의존 방향은 [아키텍처](../architecture.md)를 따릅니다. PostgreSQL 환경변수가 없을 때 SQLite를 선택하는 설정 기준은 [환경 설정 가이드](backend.md#환경-설정과-db-선택)에서 관리합니다.

## 확정한 선택

| 항목 | 기준 |
|---|---|
| 일반 엔티티의 PK | 백엔드에서 UUIDv4를 생성하고 DB의 PK 제약을 유지 |
| UUID 생성 주체 | 프론트 생성은 현재 도입하지 않음. 필요해지면 별도 계약으로 검토 |
| 상태값 | 애플리케이션 Enum으로 검증하고 DB에는 문자열로 저장 |
| 상태값의 DB 제약 | 네이티브 DB ENUM과 상태 목록을 나열하는 CHECK는 우선 사용하지 않음 |
| 상태값 검증 경로 | API 입력뿐 아니라 백그라운드 작업 등 상태값을 저장하는 경로에서도 검증 |

일반 엔티티의 PK 선택을 연결 테이블의 키 구성까지 일괄 적용하지 않습니다. 연결 테이블의 복합 PK·별도 PK 여부는 관계 설계 시 정합니다.
UUID의 DB별 저장 타입과 API에서의 표현은 별도로 정하며, UUIDv4 생성 방식을 정한 것만으로 해당 표현까지 확정된 것은 아닙니다.

## 무결성의 기본 방향

식별·필수값·유일성·참조 관계는 DB 제약으로 보장하고 입력 형식·상태값·업무 규칙은 애플리케이션에서 검증합니다.

| 보장할 내용 | DB 제약 |
|---|---|
| 행 식별 | PK |
| 필수값 | NOT NULL |
| 유일성 | UNIQUE |
| 참조 관계 | FK |

실제 테이블별 필수값·고유 조합·참조 관계는 도메인 명세에서 결정합니다. 앱에서 검증한다는 이유로 필요한 DB 제약을 생략하지 않습니다.

## 권장사항과 선택 적용

| 항목 | 적용 | 기준 |
|---|---|---|
| NULL | 권장사항 | 필수값은 NOT NULL, 선택값은 NULL 허용. ‘모름’과 ‘해당 없음’은 기능상 필요할 때만 구분 |
| 기본값 | 권장사항 | 의미가 명확한 값만 지정 |
| 기본값 생성 위치 | 권장사항 | 공통·고정 기본값은 DB, 사용자·요청 맥락이 필요한 값은 백엔드. 양쪽에 정의하면 일치시킴 |
| 인덱스 | 권장사항 | DB가 자동 생성하는 인덱스와 필요한 최소 인덱스로 시작. 추가는 실제 병목·실행계획을 확인한 뒤 판단 |
| CHECK | 선택 적용 | 상태 목록과 별개로, 반드시 지켜야 하는 안정적인 수치·범위 조건에 필요하면 검토 |

일반 엔티티의 PK 생성 위치는 위 확정 선택에 따라 백엔드입니다. 공통 기본값 생성 위치에 관한 권고를 이유로 DB 생성으로 바꾸지 않습니다.
PK·UNIQUE에 의해 생성되는 인덱스와 같은 인덱스를 중복 생성하지 않습니다. FK 인덱스의 자동 생성을 가정하지 않으며, 모든 FK에 일괄 추가하지도 않습니다.

## 네이밍 권고사항

> 적용: 권고사항. 필수 규칙이나 CI 검사로 강제하지 않습니다. 도메인 의미와 기존 모델에 맞게 조정할 수 있으며, 선택한 실제 이름은 해당 DB 명세에 기록합니다.

영문 소문자 `snake_case`를 기본으로 권장합니다. 모호한 축약·의미 없는 번호·SQL 예약어를 피하고 같은 개념에는 같은 용어를 사용합니다.
아래 이름은 설명용 예시이며 실제 테이블·컬럼 추가를 뜻하지 않습니다.

| 대상 | 권장 방식 | 예시 |
|---|---|---|
| 일반 테이블 | 대상을 나타내는 복수형 명사 | `users`, `teams` |
| 컬럼 | 값의 의미가 드러나는 이름 | `display_name`, `description` |
| 일반 엔티티의 PK 컬럼 | `id` | `users.id` |
| FK 컬럼 | 참조 대상의 단수형 또는 관계의 역할 + `_id` | `team_id`, `author_id`, `invited_by_id` |
| Boolean 컬럼 | 의미에 맞게 `is_`·`has_` 사용 | `is_active`, `has_completed_setup` |
| 단위가 있는 값 | 단위를 이름에 표시 | `duration_seconds`, `size_bytes` |
| 시각·날짜 컬럼 | 시각은 `_at`, 날짜만 있으면 `_on` | `created_at`, `published_on` |

시각·날짜의 표기 예시는 저장 타입·시간대나 공통 시간 컬럼의 필수 도입을 정하지 않습니다. PK 이름 권고와 이미 확정한 UUIDv4 생성 방식은 별개의 기준입니다.
같은 테이블을 여러 역할로 참조하면 `user_id_1`·`user_id_2`보다 `sender_id`·`recipient_id`처럼 역할을 드러내는 이름을 권장합니다.

### 연결 테이블

- 단순 연결은 두 대상의 관계가 드러나는 이름을 권장합니다. 예를 들어 게시글과 태그의 연결은 `post_tags`로 표현할 수 있습니다. 단어 순서는 기준이 되는 대상과 도메인 용어에 맞추고 동일한 관계에는 일관되게 사용합니다.
- 역할·가입일 등 관계 자체의 속성이 있으면 `team_members`처럼 의미가 드러나는 이름을 권장합니다. `mapping`·`link` 접미사를 일괄 붙이지 않습니다.
- 이름만으로 키 구성·중복 허용·삭제 방식을 결정하지 않습니다. 해당 내용은 관계 설계 시 정합니다.

### 제약조건과 인덱스

FK 컬럼명과 FK 제약조건명은 구분합니다. 예를 들어 `team_members.team_id`는 컬럼이고 `fk_team_members_team_id_teams`는 참조 관계를 보장하는 제약의 이름입니다.

| 대상 | 권장 형식 | 예시 |
|---|---|---|
| PK 제약 | `pk_<table>` | `pk_users` |
| FK 제약 | `fk_<table>_<columns>_<referenced_table>` | `fk_team_members_team_id_teams` |
| UNIQUE 제약 | `uq_<table>_<columns>` | `uq_team_members_team_id_user_id` |
| 일반 인덱스 | `ix_<table>_<columns>` | `ix_team_members_user_id` |
| CHECK 제약 | `ck_<table>_<meaning>` | `ck_items_quantity_non_negative` |

`<columns>`는 정의한 컬럼 순서대로 연결하는 방식을 권장합니다. 이름이 충돌하는 다른 조건·표현식의 제약이나 인덱스는 목적을 나타내는 접미사로 구분합니다.
DB의 이름 길이 제한과 ORM·마이그레이션 도구의 자동 명명 방식은 도구 선정 시 확인합니다. 이름 예시만 보고 불필요한 인덱스나 제약을 추가하지 않습니다.

## 도메인 설계 시 정할 항목

| 항목 | 결정할 내용 |
|---|---|
| 관계·삭제 | 관계마다 CASCADE·삭제 제한·연결 해제 등 적합한 동작 |
| 트랜잭션 | 함께 성공하거나 취소해야 하는 저장 범위 |
| 실제 데이터 제약 | 테이블별 필수값·고유 조합·참조 관계·필요한 CHECK |
| 연결 테이블 | 관계의 의미·추가 속성·중복 허용 여부·키 구성 |

선택한 내용과 이유는 해당 [DB 명세](../db/index.md)에 기록합니다. 모든 관계에 같은 삭제 방식이나 트랜잭션 범위를 미리 지정하지 않습니다.

## 추후 결정

- 금액의 구체적인 타입·단위·정밀도
- 날짜·시각의 저장 방식과 필요한 공통 시간 컬럼
- UUID의 DB별 저장 타입
- 마이그레이션 도구·절차·기존 데이터 변경 방식

마이그레이션이 미정이라는 것은 기존 데이터를 임의로 초기화해도 된다는 뜻이 아닙니다.
[API 필드 네이밍](../api/naming.md)은 이미 확정된 별도 계약이며, DB 네이밍의 권고 적용 여부가 이를 변경하지 않습니다.

문서를 갱신할 때는 [인덱스 갱신 기준](../sot.md#인덱스-갱신-기준)을 따릅니다.
