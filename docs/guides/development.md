# 개발 컨벤션

> 상태: 컨벤션 검토안. 확정된 기술 선택과 미정 항목은 [아키텍처](../architecture.md)에서 확인합니다.
> 적용 방식: [가이드 목차](index.md#필수-규칙과-권장사항)

## 필수 규칙 제안

- API 키·토큰·비밀번호·실제 개인정보를 코드·문서·로그·테스트 데이터에 넣지 않습니다.
  환경변수 예시 파일에는 키 이름과 공개 가능한 예시 값만 기록합니다.
- API·데이터 계약을 변경할 때 관련 기준 문서와 영향을 받는 호출부·테스트를 함께 확인합니다.
- 의존성 변경 시 해당 패키지 관리자에서 사용하는 설정 파일과 잠금 파일을 함께 반영합니다.

## 코드 구성과 네이밍 권장사항

- 프론트 코드는 `frontend/`, 백엔드 코드는 `backend/`에 둡니다. 상세 모듈 책임은 [아키텍처](../architecture.md)에 기록합니다.
- 백엔드는 [레이어 기반 모놀리식 구성](../architecture.md#백엔드-레이어-구성)을 따르고, 기능별 작업은 관련 레이어를 함께 완성하는 단위로 나눕니다.
- 함수·변수·파일 이름은 역할이 드러나게 짓고, 모호한 축약이나 의미 없는 번호를 피합니다.
- 한 함수·모듈에는 설명 가능한 책임을 두고, 서로 다른 기능의 변경은 가능한 한 분리합니다.
- 공통 코드는 실제로 반복되는 책임이 확인될 때 분리합니다. 예상만으로 추상화 계층을 추가하지 않습니다.
- 주석에는 코드만으로 알기 어려운 이유·제약을 적습니다. 요구사항의 복사본 대신 관련 명세를 연결합니다.
- 언어별 표기법·포맷은 스택 선택 후 도구 설정에 맞춥니다. 지금 camelCase나 snake_case를 전체 코드에 일괄 지정하지 않습니다.

## 환경과 의존성 권장사항

- 필요한 환경변수는 파트별 `.env.example`에 예시로 안내하고, 실제 값은 로컬 환경이나 배포 환경에서 관리합니다.
- 현재 `.gitignore`는 `.env`와 `.env.*`를 제외하고 `.env.example`·`.env.*.example`을 허용합니다.
- 스택 확정 시 생성물·캐시·로컬 DB·업로드 파일 등의 제외 규칙을 검토합니다.
- 패키지는 필요한 목적과 기존 도구로 해결 가능한지를 확인한 뒤 추가합니다.
- 런타임·패키지 관리자 버전과 설치·실행 명령은 파트 README에 기록합니다.

## 계약 변경과 검증

화면 동작·예외·인수 조건은 [기능 명세](../features/index.md), API·데이터 계약은 [기술 명세](../specs/index.md)에 둡니다.
변경 시 해당 명세 → 구현 → 호출부 → 테스트를 대조하고, 호환성이 바뀌면 PR에 영향을 적습니다.
검사 범위와 결과 기록은 [테스트 가이드](testing.md), PR 작성은 [Git 가이드](git-workflow.md)를 참고합니다.

## 추후 결정

- 프론트 언어·프레임워크·패키지 관리자와 버전
- 백엔드 Python·FastAPI·uv 버전과 DB 접근 도구
- 프론트 폴더 구조와 파트별 파일명·타입·오류 처리 세부 컨벤션
- 포맷터·린터·타입 검사 도구와 실행 명령

결정한 설정은 코드와 파트 README에 반영하고, 공통 선택의 이유는 [결정 기록](../decisions.md)에 남깁니다.
