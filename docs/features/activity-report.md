# 내 신고·관리자 처리 리포트

> 상태: 2026-09-11 사용자 정정 반영. 관리자 본인의 처리 이력에 진행·취소를 포함합니다. 백엔드 구현과 프론트 재구성·실제 다운로드 검증은 구분합니다.

## 내 신고

스태프는 자신이 전송한 신고의 접수·처리중·완료·취소 상태와 처리 내용을 확인합니다. 다른 스태프의 개인 신고 내역에 접근하지 않습니다. 처리 상태는 화면에서 조용히 갱신하며, 진행 변경마다 새 푸시를 보내는 흐름은 포함하지 않습니다. 취소 기록은 지우지 않습니다.

## 관리자 처리 리포트

관리자가 **본인이 수행한 처리 이력**을 관리자 화면에서 조회하고 PDF로 내보냅니다. 신고 작성자는 집계 기준이 아닙니다. 오늘·이번 주·전체 기간, 본인 프로필, 요약, 유형 분포, 상세 처리 이력을 제공합니다. 행사 전체 운영 보고서나 다른 관리자의 개인 실적 조회는 포함하지 않습니다.

| 행위 | 포함·귀속 |
|---|---|
| 담당 시작 | 시작한 관리자의 진행 이력으로 포함. 이후 해제·재배정되어도 남음 |
| 담당 해제 | 해제한 관리자의 이력으로 포함. 완료 실적 아님 |
| 분류 변경 | 변경한 관리자의 처리 이력으로 포함 |
| 완료 | 실제 완료한 관리자에게만 완료 실적 귀속 |
| 취소 | 취소한 관리자에게만 취소 실적 귀속. 기존 담당자의 취소 실적으로 자동 합산하지 않음 |
| 신고 작성·단순 지원 참여·지원 요청 개설/종료 | 개인 처리 리포트에서 제외. 원래 신고·지원 이력은 보존 |

상세 목록은 **처리 로그 한 건당 한 행**입니다. 동일 신고의 담당 시작·해제·재담당·완료가 여러 행으로 보일 수 있습니다. 요약은 중복을 제거한 신고 건수와 처리 횟수를 구분합니다. 과거 행위·발생 시각·변경 전후·본인 처리 메모를 제공하고, 신고 내용·유형·상태·구역은 현재 값으로 명시합니다. 과거 담당 시작 이력이 현재 진행 중인 신고라는 뜻은 아닙니다.

기간은 **처리 로그의 발생 시각**을 기준으로 한국 시간 오늘·월요일 시작 이번 주·전체를 사용합니다. 시작 포함·끝 제외 `[from,to)`입니다. 해당 기간에 처리 행위가 없으면 이전부터 담당 중인 신고도 그 기간에는 포함되지 않습니다. 유형 분포는 기간 내 본인이 처리한 신고를 중복 제거하고 현재 유형으로 집계합니다.

**평균 처리시간은 최종 담당 배정부터 완료까지**입니다. 접수 대기시간과 이전 담당자의 시간을 제외합니다. 선택 기간에 본인이 완료한 로그만 평균에 포함하고, 진행·취소·해제·지원은 제외합니다. 완료 0건 또는 배정 시각이 없는 경우 평균은 null입니다. 완료 후 재개방·재배정은 현재 상태 전이에서 허용하지 않습니다.

PDF는 조회와 같은 필터·요약·처리 이력을 사용하고 **페이지 크기와 무관하게 선택 기간 전체**를 출력합니다. 서버가 즉시 생성해 반환하고 파일을 보관하지 않습니다. 재조회·다운로드는 당시 데이터로 다시 생성하며 페이지를 넘기는 동안 데이터가 바뀌면 새 조회가 필요합니다. 고정 스냅샷 내보내기는 이번 범위가 아닙니다.

## 스태프 API 전환·프론트 연동

기존 `/staff/activity-report`와 `/export`는 기존 클라이언트 전환을 위한 폐기 예정 호환 API로 남깁니다. 기존 STAFF 전용·신고 작성자·접수일 기준 동작은 유지하고 OpenAPI에 deprecated를 표시합니다. 신규 관리자 화면은 [관리자 계약](../api/hackathon.md#통계pdf)을 사용하고 스태프 PDF 진입은 제거합니다. 스태프 `/staff/reports` 내 신고 조회는 유지합니다. 구 API 삭제 시점은 클라이언트 전환 확인 후 정합니다.

현재 저장소의 프론트는 임시 라우팅 골격입니다. 사용자 지정으로 프론트는 이번 백엔드 PR 책임 범위 밖입니다. 실제 관리자 화면·스태프 PDF 진입 제거는 프론트 재구성에서 수행하고 [#64](https://github.com/sku-hackathon-team08/team08/issues/64)에서 API 연결과 다운로드를 검증합니다. 백엔드 검사만으로 이 화면 흐름을 완료로 표시하지 않습니다.

사용자 ID는 기존 세션의 actor ID입니다. 새 로그인은 새 ID를 발급하므로 같은 이름의 과거 세션 실적을 합치지 않습니다. 신규 계정·세션 복구 체계는 제외합니다.

## 인수 조건

- AC-R01: 다른 스태프의 내 신고가 자신의 목록에 섞이지 않으며 취소 신고도 남습니다.
- AC-R02: 다른 사람이 작성한 신고도 본인이 처리한 행위가 포함됩니다. 다른 관리자·다른 행사의 행위는 섞이지 않습니다. STAFF의 관리자 리포트/PDF 접근은 403입니다.
- AC-R03: 접수 10:00·배정 10:05·완료 10:15인 신고의 평균 처리시간은 10분입니다. 재배정은 최종 배정부터 계산합니다.
- AC-R04: 재배정 전 담당자의 시작·해제 이력은 남고, 완료는 실제 완료자에게만 귀속합니다. 다른 관리자의 취소와 단순 지원도 실적에 섞이지 않습니다.
- AC-R05: 기간 시작·끝, 한국 시간 자정·월요일 경계와 처리 행위가 없는 기간을 검사합니다. 접수일과 처리일이 다른 사례를 포함합니다.
- AC-R06: 요약·유형 분포는 전체 선택 범위를 사용하며 PDF의 모든 이력은 페이지 조회 전체와 일치합니다. 빈 기록 PDF도 생성됩니다.
- AC-R07: 프론트 재구성 후 관리자 조회→기간 선택→전체 PDF 다운로드와 스태프 PDF 진입 제거를 실제로 검증합니다.
