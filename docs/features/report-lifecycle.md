# 신고 처리·권한·지원·이력

> 상태: 아래 확정 정책과 미정 항목을 구분합니다. PRD v1.2 · 2026-09-10. HTTP·저장 구조를 정의하는 문서가 아닙니다.

## 업무 상태

신고 상태는 **접수·처리중·완료·취소** 4종입니다. 미확인은 접수 상태에 대한 시간 조건이고, 지원요청은 처리중 신고의 별도 정보입니다. 둘을 새로운 신고 상태로 만들지 않습니다.

- 최종 전송 성공 → 접수.
- 접수에서 ‘직접 처리하기’ 성공 → 처리중.
- 처리중 담당자의 담당 배정 취소 → 접수, 현재 담당 없음.
- 처리중 담당자의 완료 처리 → 완료.
- 접수·처리중 신고의 신고 취소 → 취소.

완료·취소는 종결 상태입니다. 기록은 남으며 임의 삭제·재개를 제공하지 않습니다.

## 담당 배정과 분류 확정

관리자가 ‘직접 처리하기’를 누르면 별도 확인 모달 없이 담당 배정과 현재 화면의 유형·위험도 확정이 함께 이루어집니다. 값을 바꾸지 않았어도 관리자 확인으로 기록합니다. 단순 상세 열람은 배정이 아닙니다.

동시에 여러 관리자가 맡으려 해도 담당자는 한 명입니다. 성공한 관리자의 분류만 반영하며, 실패한 관리자의 값으로 분류를 변경하거나 확정 이력을 남기지 않습니다. 실패한 화면은 현재 담당 결과를 안내합니다.

처리중에는 담당자가 상세에서 유형·위험도를 수정할 수 있습니다. 변경자·시간·전후 내용을 남깁니다. 지원 참여로 이 권한을 넘겨받지 않습니다.

## 권한

아래 관리자는 모두 같은 행사에 접근 가능한 관리자입니다. 스태프에게 관리자 처리 권한을 부여하지 않습니다.

| 동작 | 허용 대상 | 결과 |
|---|---|---|
| 직접 처리하기 | 접수 신고를 맡으려는 관리자 | 담당 배정·분류 동시 확정 |
| 완료하기 | 현재 담당자 | 완료, 메모는 선택 |
| 유형·위험도 변경 | 처리중 현재 담당자 | 변경 이력 기록 |
| 담당 배정 취소 | 현재 담당자 | 담당 해제·접수 복귀 |
| 신고 취소 | 관리자 누구나 | 사유 필수·취소 종결 |
| 지원요청·지원요청 종료 | 현재 담당자 | 요청 시작 또는 종료 |
| 지원하기 | 활성 요청에 참여하는 다른 관리자 | 지원 참여자로 기록 |
| 지원 참여 취소하기 | 해당 지원 참여자 본인 | 자신의 참여 종료 |

## 세 가지 취소 구분

**담당 배정 취소**는 현재 담당자가 자신의 배정을 해제하는 기능입니다. 신고 원문·분류·최초 접수 시각·과거 담당 이력은 유지하고 다른 관리자가 다시 맡을 수 있습니다. [미확인 계산](command-dashboard.md)은 최초 접수부터 이어집니다.

**신고 취소**는 관리자 누구나 접수·처리중 신고를 종결하는 기능입니다. 사유는 필수입니다. 실제 취소한 사람과 사유를 기록하고 기존 담당자와 구분합니다. 목록 카드의 X도 이 기능입니다. ‘삭제’나 별도 숨김으로 표현하지 않습니다. 취소 신고는 관제 지도·목록에서 제외하지만 이력·리포트·신고한 스태프의 내역에는 남깁니다.

**지원 참여 취소**는 본인의 지원만 끝냅니다. 신고 상태와 원래 담당자를 바꾸지 않으며 이전 참여 이력을 남깁니다. 활성 지원요청이 유지되는 동안 다시 참여할 수 있습니다.

## 지원 요청 수명

1. 처리중 담당자가 지원을 요청합니다.
2. 다른 관리자가 지원하기를 누르면 지원 참여자로 기록합니다. 담당자는 그대로입니다.
3. 여러 관리자가 참여할 수 있으며 현재 인원 제한은 없습니다. 최대 인원 정책 수치는 미정입니다.
4. 참여자는 자신의 참여를 취소할 수 있습니다. 요청이 열려 있으면 재참여할 수 있습니다.
5. 담당자가 지원요청을 종료하면 **현재 지원 참여자들의 참여도 함께 종료**합니다. 신고 상태·담당 배정은 유지하고 과거 이력은 남깁니다.
6. 나중에 다시 지원을 요청하면 기존 참여자도 새로 참여해야 합니다. 자동으로 이전 참여자를 복귀시키지 않습니다.

지원 참여 기록은 현장 도착 또는 조치 완료의 증명이 아닙니다. 지원자는 담당자의 완료·분류 수정·담당 해제 권한을 얻지 않지만, 기존 관리자 공통 권한인 신고 취소는 가능합니다.

## 이력과 완료

담당자만 완료할 수 있고 완료 메모는 선택입니다. 접수·담당·분류 변경·지원 요청 및 참여·완료·취소의 행위자와 시각을 추적할 수 있어야 합니다. AI 제안·스태프 수정·관리자 확인을 구별합니다. 신고 취소와 개인정보 보존 종료에 따른 삭제는 다른 작업입니다.

## 인수 조건

- AC-L01: 배정 시 현재 유형·위험도가 함께 확정됩니다. 값을 수정하지 않은 경우도 관리자 확인으로 남습니다.
- AC-L02: 두 관리자의 동시 배정에서 한 명만 담당하며 실패자의 분류가 반영되지 않습니다.
- AC-L03: 다른 관리자는 담당자의 신고를 완료·분류 수정·담당 해제할 수 없습니다.
- AC-L04: 같은 행사 다른 관리자도 필수 사유를 입력하면 신고를 취소할 수 있습니다. 사유 없이는 취소되지 않습니다.
- AC-L05: 담당 배정 취소는 신고 취소가 되지 않으며 다른 관리자가 다시 배정받을 수 있습니다.
- AC-L06: 완료 메모 없이 담당자가 완료할 수 있습니다.
- AC-L07: 여러 지원자의 참여·본인 취소·재참여가 원래 담당자를 바꾸지 않습니다.
- AC-L08: 지원요청 종료 시 활성 참여가 함께 종료되고 재요청 시 이전 참여자를 자동 복귀시키지 않습니다.
- AC-L09: 목록 X로 취소해도 기록이 남으며 관제 지도·목록에서는 제외됩니다.

## 해커톤 보완 정책 — 2026-09-11 확정

신고 완료·취소·담당 해제 시 활성 지원요청과 참여를 모두 함께 종료합니다. 다시 지원을 요청하면 새 ID로 시작하고 이전 참여자는 새로 참여합니다. 처리·지원 변경은 버전을 증가시키며 동시에 변경하면 먼저 성공한 하나만 반영하고 나머지는 새로고침 후 재시도합니다. 실패한 변경은 분류·이력·버전을 남기지 않습니다.

담당 해제에는 사유를 받지 않고 신고 취소만 사유를 필수로 받는 현재 API를 적용합니다. 장기 개인정보 보존·관리자 탐색 UI는 후속 범위입니다.
