# SOT — 기준 문서

SOT(Source of Truth)는 주제별로 기준이 되는 문서를 뜻합니다.
같은 요구사항·계약은 한 곳에서 관리하고, 다른 문서와 외부 협업 도구에서는 원본을 링크합니다.
이 문서는 기준 문서의 위치와 책임을 안내합니다. 실제 요구사항·계약은 아래 문서에 작성합니다.

## 주제별 기준

| 주제 | 문서 | 책임 |
|---|---|---|
| 제품 | [PRD](prd/index.md) | 주제별 문제·사용자·목표·범위·우선순위·성공 기준 |
| 기능 | [기능 명세](features/index.md) | 사용자 시나리오·화면 동작·예외·인수 조건 |
| 기술 계약 | [기술 명세](specs/index.md) | API·데이터 모델·공통 오류 등 구현 간 약속 |
| 시스템 | [아키텍처](architecture.md) | 시스템 경계·파트별 책임·코드 위치 |
| 개발 흐름 | [SDD](sdd.md) | 명세 확인·구현·검증을 연결하는 잠정 작업 흐름 |
| 결정 이력 | [결정 기록](decisions.md) | 선택·이유·날짜·영향받는 문서 |

루트 README는 프로젝트 소개와 실행 진입점입니다. `AGENTS.md`·`CLAUDE.md`는 docs를 읽는 경로만 안내합니다.
파트별 README는 설치·실행·검증 명령을 안내하며 상세 요구사항·계약은 docs를 링크합니다.

## 문서 상태

- **미정:** 아직 결정하지 않은 항목. 작성 틀과 예시를 실제 요구사항으로 취급하지 않습니다.
- **검토안:** 제안이 작성됐으나 확정되지 않은 상태.
- **확정:** 팀에서 채택한 요구사항·계약. 채택된 내용을 해당 문서에 반영합니다.
- **폐기:** 더 이상 적용하지 않는 내용. 대체 문서나 결정 기록을 연결합니다.

기준 문서로 지정했다는 사실과 문서 내용의 확정 여부는 별개입니다.
명세 상태와 구현 완료 여부도 별개이며, 구현은 코드·실행 결과·테스트로 확인합니다.

## 작성과 변경

- 본문은 한국어, 개별 파일명은 영문 kebab-case를 사용합니다. 문서 목차는 `index.md`로 통일합니다. 프로젝트 소개·파트 실행 안내는 `README.md`에 둡니다.
- 명세에는 상태·관련 문서·미결정 사항을 표시합니다. 담당자가 정해지면 함께 기록합니다.
- 기능 명세에는 요구사항과 인수 조건을, 기술 명세에는 구현 간 계약을 작성하고 서로 링크합니다.
- 새로운 결정은 관련 기준 문서에 반영하고 중요한 선택의 이유는 결정 기록에 남깁니다.
- 문서와 코드가 다르면 기대 동작 변경인지 구현 오류인지 구분하고 차이·영향·검증 결과를 기록합니다.
- 문서를 이동할 때 상대 링크·앵커·코드 주석·에이전트 안내의 경로를 함께 확인합니다.

미정 사항은 제안과 가정을 드러내고 다룹니다. 이 문서는 새 승인 절차를 추가하지 않습니다.
